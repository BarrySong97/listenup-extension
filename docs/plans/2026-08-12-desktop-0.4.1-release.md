# ListenUp Desktop 0.4.1 来源切换与 Modal 修复发布

- 日期：2026-08-12
- 状态：已完成
- Plane：LISTENUP-12
- 功能与修复：LISTENUP-11
- 实施计划：`docs/plans/2026-08-12-desktop-browser-to-embedded-switch.md`

## 发布目标

把 BrowserSource 到 Desktop 同窗播放的主动切换、非输入区域粘贴识别、HeroUI 底部 Modal、
输入焦点与 macOS 复制粘贴修复发布给官网新安装用户和 0.4.0 应用内更新用户。Modal 打开时
使用覆盖完整窗口（含 Header）的 Mask，不支持拖窗；点击 Dialog 外 Mask 后关闭，再由 Header
拖动窗口。

## 发布范围

- Desktop 版本从 0.4.0 升到 0.4.1；Extension 与 Website 版本不变。
- 同步 `package.json`、Tauri 配置、Cargo manifest / lockfile 与 Desktop 发布基线文档。
- 推送 annotated tag `v0.4.1`，由 `release-desktop.yml` 构建 Apple Silicon DMG、updater
  `.app.tar.gz`、minisign 签名和 `latest.json`，全部成功后自动公开 Release。
- Chrome Web Store 不随本次发布更新；BrowserSource 现有 native messaging 协议保持不变。

## 风险与回归

- 正式构建必须来自干净 tag；workflow 任一步失败应保持 draft，不手工公开不完整资产。
- `latest.json` 必须指向 `github.com/.../releases/download/v0.4.1/`，不能使用 GitHub assets API。
- 发布资产必须包含 DMG、updater `.app.tar.gz`、签名和 `latest.json`；签名/公证状态以 workflow
  与 Release 资产为准。
- 本地 DEV bundle 仅用于交互回归，发布前必须清理仓库 `target` 下 bundle，正式资产只认 tag CI。
