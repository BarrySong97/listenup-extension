# 内容脚本测试策略

> 目的: 定义内容脚本模块当前实际可执行的验证方式，避免“应该测什么”每次重新讨论
>
> 源码路径: `src/pages/content/`
>
> 覆盖范围: 构建检查、手工回归清单和高风险改动时的额外验证

## 源码定位

- 主路径: `src/pages/content/`
- 相关路径: `package.json`

## 当前现状

仓库当前没有内容脚本专属的自动化测试套件。最低验证线是：

- 构建通过
- 相关场景的手工回归完成

## 最低验证命令

```bash
pnpm build
```

如果改了 Firefox 特有行为，再补：

```bash
pnpm build:firefox
```

## 手工回归清单

改内容脚本 UI 或交互时，至少检查：

- 在 YouTube watch 页面能正常挂载面板
- 视频切换后面板会跟随新 `videoId` 重建
- 字幕能加载，loading / empty / error / ad 状态合理
- 点击字幕能跳转到对应时间
- 当前字幕高亮和自动滚动正常
- 复制、解释、下载、循环播放、录音等相关入口未被破坏
- 麦克风菜单展开时，当前所选输入设备的电平反馈会随说话变化
- 连续录多个 take 后，播放会优先命中当前最新录制的一段

改字幕加载链路时，额外检查：

- 首次加载是否命中正确字幕轨
- 字幕缓存是否仍可复用
- 页面桥接 fallback 是否仍可工作
- 无字幕视频不会报致命错误

改 Shadow DOM 或样式注入时，额外检查：

- 样式不污染 YouTube 原生页面
- Dropdown、hover、选区浮层等 overlay 行为没有错位
