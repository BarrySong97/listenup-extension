# ListenUp Desktop 0.5.2 商店 Extension 协议兼容热修复发布

- 日期：2026-08-14
- 状态：已完成
- Plane：LISTENUP-19
- 修复：LISTENUP-17
- 决策：[ADR-0018](../decisions/0018-desktop-backward-compatible-native-protocol.md)

## 发布目标

修复 Desktop 0.5.1 与 Chrome 商店 ListenUp 1.5.2 的 Native v4 协议不兼容。Host socket 已连接时，
Desktop 必须接受 v4 ready session、显示并持久化字幕，为缺少字段的 v4 cursor 合成播放世代，并以
v4 回发播放控制；v5 的完整协议和 Embedded 退出隔离保持不变。

## 发布范围

- Desktop 版本从 0.5.1 升到 0.5.2；Extension 与 Website 版本不变。
- 同步 `package.json`、Tauri 配置、Cargo manifest / lockfile。
- 推送 annotated tag `v0.5.2`，由 `release-desktop.yml` 构建、签名、公证并公开 DMG、updater
  `.app.tar.gz`、签名与 `latest.json`。
- 线上兼容基线为本机 Chrome 商店 ListenUp 1.5.2，其 bundle 明确使用 Native v4 且 cursor 不含
  `playbackEpoch`；自动测试使用相同 JSON 形状。

- `pnpm build:desktop` 成功，产物版本与 bundle version 均为 `0.5.2`。
- 本地候选覆盖安装到 `/Applications/ListenUp Desktop.app`，整包 ad-hoc 签名后通过
  `codesign --verify --deep --strict`，主进程与 Chrome Native Messaging 桥接进程均正常运行。
- 商店 Extension 1.5.2 重新连接后，日志分界点之后不再出现
  `ignored invalid Native Messaging JSON: missing field playbackEpoch`，证明 v4 消息已进入兼容路径。

## 风险与回归

- 0.5.1 已在生产证明“只测仓库 HEAD 两端”不足；0.5.2 必须锁定商店 1.5.2/v4 的真实消息形状。
- v4 兼容不得让缺少 `playbackEpoch` 的 v5 cursor 静默降级，也不得削弱 bridge/session/video 身份门。
- workflow 任一步失败保持 draft，不手工公开不完整资产；正式资产只认 tag CI。
